# Wi-Fi/Bluetooth passive boot observation

Historical diagnostic design used for the paired boots on 2026-11-02; not installed by the production image build. Existing GTX RX-preallocation driver, firmware and DTB retained. /boot/armbianEnv.txt backup and staged-file hash manifest: /var/backups/h96-wifi-boot-observe-20261102/. Boot arguments enable GPIO, clock, regulator, runtime-PM and MMC trace events from kernel tracing startup. Filtered function tracing records pinctrl/mux changes, SDIO set_ios and UART termios calls. Buffer 8192 KiB per CPU. Trace overhead can affect timing; inspect overrun stats before assuming completeness.

GPIO mapping from DTB: SDIO data GPIO1_PA0..PA3 (32..35), CMD PA4 (36), CLK PA5 (37), LED PA6 (38), host wake PA7 (39), UART/BT GPIO1_PB* and PC* (including BT wake/reset 48/49/50), 32k clock GPIO1_PC3 (51), Wi-Fi reset GPIO4_PA4 (132). Other GPIO4 changes retained except display pins 147/148 excluded after the early filter is installed. Prior to that filter the kernel boot trace records those too.

h96-wifi-trace-arm.service is a short oneshot before systemd-modules-load with DefaultDependencies=no and no journald/udevd ordering edges. It sets MMC host filter mmc2 and GPIO filter, adds kprobes decoding dw_mci_set_ios (clock, vdd, bus/power modes, width, timing, signal voltage), Rockchip mux arguments, and UART cflag/ispeed/ospeed. Kprobe field layouts are based on matching ARM64 6.1.172 mmc_ios and ktermios headers. All four kprobe definitions were successfully registered then removed in preflight without enabling them. Unsupported optional probes are logged without blocking modules-load beyond service timeout (8 seconds).

h96-wifi-boot-observe.service is Type=simple, DefaultDependencies=no and runs after arm. It drains boot trace and samples every 250ms for 90 seconds: gpio debugfs, pinmux/pinconf/handles, clock/regulator summaries, MMC2 ios, host/card runtime PM, rfkill, module parameters, HCI power, UART PM, serial driver info and IRQ counts. Only changed snapshots are stored with monotonic timestamps. It records live DT, kernel log and Bluetooth/rfkill/NetworkManager/wpa service journal. No scan/rescan, GPIO writes, SDIO register reads or UART device opens are performed by the collector. Reading debugfs/sysfs still causes some observation overhead.

Output: /run/h96-wifi-boot-trace while collecting; copied after 90 seconds to /var/log/h96-wifi-boot-trace/BOOT_ID. Function tracing lacks argument values before kprobes attach; boot events and snapshots complement it. Snapshot polling can miss short transitions, and function calls reflect requested software changes, not proof of physical voltage or chip-internal firmware state. Per-CPU stats record trace loss/overruns.

After successful collection, original boot config is restored only if current config matches the staged hash, then both collection services are disabled for future boots. Active kernel trace is stopped. If boot fails or collection does not finish, restore /var/backups/h96-wifi-boot-observe-20261102/armbianEnv.txt to /boot/armbianEnv.txt from mounted SD. Disable/remove the two symlinks in /etc/systemd/system/sysinit.target.wants if needed. No driver rollback is required for tracing alone.

Validation performed: shell/Python syntax, systemd-analyze verify, availability of every requested event/function, successful creation/removal of all optional argument probes. The subsequent paired boots completed collection and the services disabled themselves. See the [GPIO38 findings](WIFI_GPIO38_LED_RESTORE_FIX_2026-11-02.md) for observed results.
